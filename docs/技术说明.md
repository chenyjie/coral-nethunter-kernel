# 技术说明

本内核相对参考 ROM 原装内核（`4.14.357-0xSoul-gfe1e185ec666`，manual hook，WLAN 为模块）的改动，以及每项的取值理由。逐行配置差异见 `config/config-delta-vs-stock.diff`。

---

## 1. clang 编译目标必须是 `aarch64-linux-gnu`

coral 是 4.14 内核，官方构建的 clang target 是 `aarch64-linux-gnu`。

源码树 `0xSoul24/kernel_google_msm-4.14` 的 `Makefile` 在老式分支里把 `--target` 取自 `CROSS_COMPILE` 前缀，而树自带 `build.config.common` 里是 `CROSS_COMPILE=aarch64-linux-android-`，会得到 `aarch64-linux-android`。**必须改成 `aarch64-linux-gnu`，否则内核开机卡 Google 标志。**

修复（见 `patches/0001-clang-target-aarch64-linux-gnu.patch`）：

```makefile
-CLANG_FLAGS	+= --target=$(notdir $(CROSS_COMPILE:%-=%))
+CLANG_FLAGS	+= --target=$(CLANG_TARGET_FLAGS)
```

构建脚本已把这个补丁当作前置条件检查。

## 2. KernelSU 用 SUSFS hook

三个 hook 方式是 `KernelSU/kernel/Kconfig` 里的**互斥 choice**：`KSU_TRACEPOINT_HOOK` / `KSU_MANUAL_HOOK` / `KSU_SUSFS`。

这棵树的 su 接管钩子（`ksu_handle_execveat` 等，`fs/exec.c`、`fs/open.c`）全部写在 `#ifdef CONFIG_KSU_SUSFS` 下。**SUSFS 是这棵树原生支持的勾法**，关掉它 su 就永远拿不到 root。

```
CONFIG_KSU=y
CONFIG_KSU_SUSFS=y
# CONFIG_KSU_MANUAL_HOOK is not set
```

KernelSU 子模块需完整克隆并 checkout `v4.2.0-rc2`。版本号由 `KernelSU/kernel/Kbuild` 算出：`30000 + rev-list --count HEAD + 700`，该 tag 对应 **35144**，与 ReSukiSU 管理器同级。

`patches/optional/0003` 里的 `fs/stat.c` / `fs/read_write.c` 锚点是 manual hook 用的，在本配置下被 `#ifdef CONFIG_KSU_MANUAL_HOOK` 条件编译掉，属惰性代码。

## 3. 内置 WiFi 不工作，改用外置 USB 网卡

```
CONFIG_QCA_CLD_WLAN=y      # 高通内置 WLAN 驱动（qcacld）
CONFIG_ICNSS=y
CONFIG_88XXAU=y            # 外置 USB 网卡：8812au / 8821au
```

**当前已知问题：内置 WiFi 不工作。** 原装的 qcacld 驱动是模块，`/vendor/lib/modules/wlan.ko` 带符号 CRC，而 `/vendor` 是 **EROFS 只读**，任何 overlay 方案都晚于 vendor init 的 `insmod`（约 2.07 s）而不生效；编进内核后（`CONFIG_QCA_CLD_WLAN=y`）没有模块、没有 CRC、没有加载顺序依赖，但 `wlan0` 仍不出现。

**因此无线能力与上网改走外置 USB 网卡。** 本内核已内建 `CONFIG_88XXAU=y`（aircrack-ng 的 `rtl8812au` 驱动，覆盖 **8812au / 8821au** 族），插上即可用。

## 4. CFI 机制保留，校验降级为告警

```
CONFIG_LTO_CLANG=y
CONFIG_CFI_CLANG=y
CONFIG_CFI_CLANG_SHADOW=y
CONFIG_CFI_PERMISSIVE=y
```

`CONFIG_88XXAU`（aircrack-ng/rtl8812au，`v5.6.4.2_35491.20191025`）**不是 CFI-clean**：驱动内部有几处间接调用的函数签名与实际目标不一致。在 enforce 模式下 `handle_cfi_failure()` 会直接 `panic()`，叠加 `CONFIG_PANIC_ON_OOPS=y` 会让插网卡变成重启循环。

`CONFIG_CFI_PERMISSIVE=y` 把这组失败降级成 `WARN_RATELIMIT`，间接调用照常执行到目标函数，网卡功能不受影响。

**这是权衡**：CFI 加固在 88XXAU 这一处被削弱。要恢复强制 CFI，需要修驱动里的间接调用（上游仓库 2024 年已归档）。

## 5. 崩溃现场落盘（可选）

```
CONFIG_KPANIC_LOGGER=y
```

`src/kpanic_logger.c`。coral 的崩溃日志原路径不可用：引导器强塞 `console=null`，ramoops 是 AES-GCM 加密的且密钥拿不到，`/sys/fs/pstore` 常年为空。

这个驱动把内核日志以**纯文本**写进 `alt_ramoops_region`（物理地址 `0xA49FF000`，2 MB），panic / oops 时经 `kmsg_dumper` 触发写入，并在各 initcall 阶段写进度标记。开机后 root 直接从 stock 的 `/dev/access-ramoops` 读回，不依赖 pstore 与解密。

它是调试工具，正式使用可以不放：去掉 `patches/0002` 和 `CONFIG_KPANIC_LOGGER=y` 即可。

## 6. 诊断探针

```
CONFIG_PANIC_ON_OOPS=y
CONFIG_DETECT_HUNG_TASK=y  CONFIG_BOOTPARAM_HUNG_TASK_PANIC=y  CONFIG_DEFAULT_HUNG_TASK_TIMEOUT=30
CONFIG_SOFTLOCKUP_DETECTOR=y  CONFIG_BOOTPARAM_SOFTLOCKUP_PANIC=y
CONFIG_RCU_PANIC_ON_STALL=1
CONFIG_WQ_WATCHDOG=y
```

作用是把"静默挂死"逼成"panic"，让日志有落点。`RCU_PANIC_ON_STALL` 是**数值型**符号，必须用 `scripts/config --set-val RCU_PANIC_ON_STALL 1`（`-e` 无效）。

日常使用可以关掉其中任意项；它们不影响功能。
